## 1. 何を集めているか（定義）

集める対象は「HPが古い会社」ではない。

**「公開メールがあり、サイト側の粗が事実で示せ、66,000円の差し替え＋本番公開が刺さりうる中小」**

| 買う人の心理 | 収集で見るもの |
|---|---|
| 「見せ方が悪いだけ」と感じる | 事実ベースの粗 2点以上 |
| 「66,000円なら試せる」 | 支払いシグナル 1点以上 |
| 「メールで決まる」 | **公開メール必須**（電話のみは別トラック） |
| 「勝手に作られたデモが嫌」 | 怒りの種を減らす除外（下表） |

業種は固定しない。  
ただし **Phase 1（2026-08-22〜）は工務店（`vertical=koumuten`）のみ送信**。税理士・葬儀等は雛形完成まで Hunter しても `queued` にしない。

**学習のために「欠陥タイプ」でバッチを固める**（例: 今週は http + telなし だけ）。

## 2. 6ゲート（全部通過で初めて CSV に入れる）

| # | ゲート | 必須 | 合格条件 | 不合格時 |
|---|---|---|---|---|
| G0 | 連絡可能性 | ✅ | サイト上・GBP・署名から **実在するメール** が取れる | 捨てる（推測で作らない） |
| G1 | 粗（需要） | ✅ | **G1検証プロトコル**通過の粗が **2点以上** | 捨てる or トラックB候補メモのみ |
| G2 | 支払いシグナル | ✅ | 下表Bから **1点以上** | 捨てる |
| G3 | 買い取り適合 | ✅ | 「差し替えで足りそう」／巨大カスタム需要ではない | トラックBへ振る |
| G4 | 衝突なし | ✅ | 過去30日に未送信・停止リスト外・既存カスタム商談中でない | スキップ |
| G5 | デモ公開可能 | ✅ | 差し替え後 **公開URLを出せる経路**がある（Pages等） | 制作キューに入れない |

**G0 が最重要。**  
現行 `sales_prospects.csv` は約51社中メールあり約16社。  
古いリストを「ターゲット」と呼ぶと、送れない在庫が増えるだけ。

印刷用チェックリスト: [`demo_buyout_audit_checklist.md`](./demo_buyout_audit_checklist.md)  
機械補助: `node tools/site-audit.mjs <url>`（最終URL・tel:を表示。C0は人手）

### G1 検証プロトコル（誤診防止・必須）

過去ミス（マキノ＝旧ドメインだけ古い／HTTPSなのにHTTP指摘／tel:見逃し／見当違いの課題）を再発させない。  
粗を書く前に **下表を全部チェック**。1つでも未確認ならリストに入れない。

| 検証 | 手順 | 禁止（過去ミス） |
|---|---|---|
| **C0 正規サイト** | 社名で検索し、提示URL以外に **より新しい公式**（別ドメイン・.com等）がないか確認。GBPの「ウェブサイト」も見る | 旧ドメインだけで「古い」と断定（マキノ型） |
| **C1 HTTPS** | `http://` と `https://` の両方を試し、**最終到達URL**で判定。301でhttpsなら「https未対応」と書かない | アドレス欄の表記やリストのhttpだけで断定 |
| **C2 tel:** | HTMLに `href="tel:` があるか。スマホ幅で番号がタップ発信できるか | 「電話はあるが発信できない」と誤記 |
| **C3 表示** | 実ブラウザ or DevTools〜390px。JS描画完了まで待つ | 「壊れている」とauditだけで断定（川津型） |
| **C4 更新** | コピーライト・新着・Last-Modifiedは参考。新公式が別にある場合は更新判定に使わない | 旧サイトのCopyright年だけで飢餓感を付ける |
| **C5 課題文** | メールの課題①〜③は、この検証で **合格した粗だけ**。1課題＝1事実 | 推測・主観・測っていないSEO/速度 |

**チェック用ワンライナー（記録に残す）:**

```
C0: 別公式なし / あり→URL=___ → ありなら旧URLは対象外
C1: final=https|http  (redirect: yes/no)
C2: tel:=yes|no  (count=N)
C3: mobile390=ok|broken  (note=__)
C4: update_signal=__  (year=__ / none)
粗: (1)__ (2)__ (3)__
```

`audit_notes` には上記を短く残す（日付つき）。  
初回メールの課題は `audit_notes` からコピーするだけ（新規の指摘をメール時に足さない）。

## 3. スコア（収集時の優先付け）

必須は G0〜G5。スコアは **どの順でデモを作るか** に使う。

| 軸 | 加点 | 根拠 |
|---|---|---|
| 粗が「導線・信頼」系（http / telなし / CTA弱い） | +3 | 55kデモで一瞬で差分が分かる |
| スマホ破綻が目視で明確 | +2 | デモの強みと直結 |
| 0120 / 店舗集客 / 法人 | +2 | 予算が出やすい |
| GBPレビュー 10〜200 | +2 | 動いているが大手でない |
| メールが個人名 or 代表っぽい | +1 | info@より開封・決裁に近い |
| 更新が2020以前 or HPほぼ無し | +1 | 飢餓感 |
| 既にモダンCMSで導線も良い | −5 | 送らない |
| 全国FC・レビュー数百超 | −5 | 送らない |
| メール推測しかない | −∞ | リスト禁止 |

**同じ週に入れるのはスコア上位から。**  
週の収集上限（初期）: **合格 8社 / 週**（制作・公開のボトルネックに合わせる）。

## 4. メールの取り方（推測禁止ルール）

### やってよい

1. 現行HPの `mailto:` / お問い合わせページ記載
2. Googleビジネスプロフィールのメール（出ている場合）
3. 会社概要PDF・採用ページに明記されたもの
4. 既存リストで「★メール公開」と検証済みのもの

### やってはいけない

- `info@ドメイン` をドメインから機械生成して送る
- 名刺交換していない個人Gmailを第三者から拾う
- フォームしかない先に「仮メール」を捏造
- 複数アドレスを一斉に試し撃ち

フォームのみの会社は **トラックA対象外**（電話リストは別運用。買い取りメール導線には載せない）。

---

## 5. 除外（収集段階で切る）

| 除外 | 理由 |
|---|---|
| メールなし / フォームのみ | 送れない＝在庫汚染 |
| サイトが新しく導線も整っている | 返信率を壊す |
| **別ドメインに新公式がある**（旧URLだけ古い） | マキノ型。旧を突くと即却下 |
| **http表記だがhttpsへ301** | 「https未対応」と書けない |
| **tel:があるのに「発信できない」と書く予定** | 誤診。その粗は使わない |
| 大手・FC・レビュー過密 | 55kが刺さらない |
| 公営・協会・意思決定者不在 | 受注不能 |
| 過去に「不要・STOP・怒り」 | 法務・信頼 |
| 既存デモ送付済・カスタム商談中 | 二重営業 |
| 業法・医療広告が厳しく文案リスクが高い先（初期） | 初期は避ける（慣れてから） |
| auditだけで断定した粗しかない | 川津型誤診断の再発防止 |

## 6. 収集ソース（優先順）

「業種ディレクトリを漁る」より、**欠陥が観測しやすい入口**から入る。

| 優先 | ソース | 取り方 |
|---|---|---|
| 1 | 既存 `sales_prospects.csv` のメールあり × S/A | 再診断して G1〜G5 を通す。クラウド正本: `buyout-ops/sales_prospects.csv` |
| 2 | Googleマップ（地域×業種は可変） | GBP → サイト → メール抽出 → audit＋実機 |
| 3 | 自社デモ実績の近傍（同エリアの類似粗） | 同欠陥タイプでバッチ学習 |
| 4 | 紹介・既存関係 | 最優先だが数は少ない |

**初期バッチ推奨（学習用）:**  
「http または SSL警告」かつ「公開メールあり」かつ「法人」だけを **5社**。  
業種を混ぜてよい。欠陥タイプは揃える。

## 8. Hunter がやらないこと

- メール送信
- デモHTMLの本制作・デプロイ
- Stripe / 素材フォーム操作
- 「良さそう」だけのリスト追加
- Instantly 等への投入（初期禁止）

---

## 9. 週次の止め方（学習ループ）

| 指標 | 初期の見方 |
|---|---|
| 送信→返信率 | 2週で **2%未満** かつ苦情あり → その欠陥バッチを捨てる |
| 返信→決済率 | 質問ばかりで決済ゼロ → 初回メールの価格/範囲の書き方を直す |
| 決済→素材提出率 | 低い → 決済後メール（intake）導線を点検 |
| STOP/怒り | **1件でも** → 文面・対象・オプトアウトを即見直し |

Proofset と同じ: **セグメントが死んだら捨てる。意地で送らない。**
