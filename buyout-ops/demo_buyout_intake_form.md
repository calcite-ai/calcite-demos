# デモ買い取り — 素材回収フォーム設計

> Step 2 成果物（2026-08-20）／ **v1.1（2026-08-21）** 公開切替フィールド追加  
> 商品定義: [`demo_buyout_plan.md`](./demo_buyout_plan.md)（66,000円・切替込み）  
> 既存のカスタム用チェックリスト（`templates/materials_checklist_calcite.html`）とは別。短く・必須だけ。

## 目的

決済後に **打ち合わせなし** で「差し替え」と「既存ドメイン本番公開」ができる情報を回収する。  
長いヒアリングシートは使わない。未提出で納期が止まらないよう、必須を最小化する。

---

## フォーム基本

| 項目 | 内容 |
|---|---|
| 名称 | デモサイト 素材ご提出フォーム |
| タイミング | 決済完了メール直後 |
| 目安回答時間 | **10〜15分**（切替情報込み） |
| 提出期限 | 決済から **48時間以内**（努力目標） |
| 未提出ルール | 7日未提出 → 制作保留メール |
| ファイル上限 | ロゴ1 + 写真5（各10MB目安） |
| 受け取り先（初期） | オーナーGmail（`kenta.hino1106@gmail.com`） |
| 実装（初期） | **本番CF7公開済み** `https://www.calcite-ai.jp/?page_id=23` |

注文ID（Stripeの `cs_xxx` 等）を隠しフィールド or 冒頭入力で紐づける。

## セクション構成

### 0. ご注文の確認

| フィールド | 必須 | 型 | 備考 |
|---|---|---|---|
| ご注文メールアドレス | ✅ | email | 決済時のメールと照合 |
| 注文ID（わかれば） | — | text | メールに記載。任意 |
| **希望デモ案（A/B）** | ✅ | select | 営業時に見せた2案のどちらか。決済紐付け保険 |

説明文:

```
ご購入ありがとうございます。
デモHPを御社用に差し替え、既存ドメインで本番公開するため、下記をご記入ください。
必須項目だけで制作を開始できます。写真やロゴが無くても問題ありません。
公開切替に必要な接続情報も、このフォームで回収します。
```

| フィールド | 必須 | 型 | 制約・ヒント |
|---|---|---|---|
| 正式な会社名 / 屋号 | ✅ | text | ロゴ表記と揃える |
| 代表者名 | ✅ | text | |

| 営業時間 | ✅ | text | 例: 平日 9:00–18:00 |
| 定休日 | ✅ | text | 例: 土日祝 / 不定休 |

---

### 2. 掲載内容（必須）

| フィールド | 必須 | 型 | 制約・ヒント |
|---|---|---|---|
| 事業内容 | ✅ | textarea | **200〜800字**。箇条書き可。整文はこちらで可だが新規執筆は含まない |
| 掲載したいサービス名 | ✅ | textarea | **3〜6項目**。1行1サービス（例: 外壁塗装 / 屋根修理） |
| 各サービスの一言説明 | — | textarea | 任意。無ければサービス名のみ掲載 |
| キャッチコピー希望 | — | text | 任意。無ければデモの型を流用 |
| 問い合わせ導線の希望 | ✅ | 選択 | `電話` / `メール` / `簡易フォーム` のどれか1つ |

事業内容が800字超 → 「要約して掲載してよい」前提で受け、超過分は使わない。  
サービスが7項目以上 → 先頭6件のみ採用、と説明文に明記。

---

### 3. 本番公開・切替（必須）※v1.1

プランに **既存ドメインでの本番公開** が含まれます。どちらか1方式。

| フィールド | 必須 | 型 | 制約・ヒント |
|---|---|---|---|
| 公開したいドメイン | ✅ | text | 例: `example.co.jp`（www有無も明記） |
| 切替方式 | ✅ | select | `S: 既存サーバーへ設置` / `D: DNSで向き先変更` |
| 【S】サーバー会社名 | 方式Sで✅ | text | 例: エックスサーバー / ConoHa / さくら |
| 【S】接続方法 | 方式Sで✅ | select | FTP / SFTP / ファイルマネージャ / その他 |
| 【S】接続情報 | 方式Sで✅ | textarea | ホスト・ユーザー名・パスワード等。提出後こちらで安全に扱い、作業完了後は破棄方針 |
| 【S】設置先の目安 | — | text | 例: public_html / 現行トップのディレクトリ |
| 【D】ドメイン管理会社 | 方式Dで✅ | text | 例: お名前.com / ムームー / サーバー同社 |
| 【D】設定の進め方 | 方式Dで✅ | select | `指定レコードを自分で入れる` / `管理画面の権限を一時付与` / `画面共有で一緒に設定（メール調整）` |
| 【D】連絡用メモ | — | textarea | ログインURL・担当者など（パスワードは必要な場合のみ） |
| 希望切替日 | ✅ | text | 目安で可。例: 平日夜 / ○月○日以降 |
| 旧サイトの扱い | ✅ | select | `トップを差し替え（コピーを残す）` / `別フォルダに旧サイトを残す` / `相談したい` |

説明文（本番CF7に表示・2026-08-21更新）:

```
本番公開まで本プランに含まれます（新規ドメイン取得・新規サーバー契約は含みません）。
切替方式は迷ったら「S」（いまのサーバーにファイルを置く）。
各項目に「どこを見ればわかるか」の短いヒントをフォーム上に表示する。
わからない／後送で提出可（その項目だけ後案内）。接続情報は作業後に保管しない。
```

## 受領後の社内チェック（人が見るのはここだけ）

提出を開いたら、この順で確認。

1. 必須フィールドが空でないか（**切替方式・ドメイン含む**）
2. 電話・メール・住所がサイト掲載可能な表記か
3. サービスが3〜6項目に収まっているか（超過は先頭6）
4. 事業内容が200字未満 → 追記依頼 / 800字超 → 要約して使う
5. 写真が5点超 → 先頭5 or 顧客に優先指定を聞く（1往復まで）
6. 注文IDとメールが決済と一致するか
7. 方式Sなら接続情報でログイン試行できるか / 方式DならDNS担当が明確か
8. 希望切替日が現実的か（連休直前など）

問題なければ `status=ready`（制作開始）。  
切替情報だけ後送可 → `status=ready_content`（差し替え先行）。  
不足があれば **1通だけ** 不足項目を返す。往復を増やさない。

## カスタム制作用チェックリストとの違い

| | デモ買い取り（本フォーム） | カスタム（既存） |
|---|---|---|
| 長さ | 短（必須中心＋切替） | 長（写真・想い・参考サイト） |
| 文章 | 顧客提出文を整える程度 | 原稿作成あり |
| 色・参考サイト | 聞かない | 聞く |
| ドメイン/サーバー | **聞く（本番切替が本体）** | 聞く |
| 目的 | 差し替え＋切替を止めたくない | 要件を深く取る |
