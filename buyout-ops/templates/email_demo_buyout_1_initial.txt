# ----- 課題の書き方（社内用・メール本文には貼らない）-----
#
# 必ず現行URLを開き、事実ベースで2〜3点。言い切りすぎない。
#
# 使える切り口の例:
#   ・問い合わせ導線が弱い
#     「電話番号はあるが、スマホでタップ発信できない」
#     「フォームはあるが、第一画面にCTAが見えない」
#     「お問い合わせページまでの導線が分かりにくい」
#   ・セキュリティ / 信頼
#     「httpのまま（鍵マークが付かない）」← httpsか必ず確認
#     「古い証明書警告が出る」← 実ブラウザで確認
#   ・スマホ表示
#     「スマホで文字が小さい / 横スクロールする」← 実機かDevToolsで確認
#     「メニューやボタンが押しにくい」
#   ・情報が伝わりにくい
#     「事業内容がテキストの羅列で、何ができるか一目で分からない」
#     「更新が止まっており、稼働中か判断しづらい」
#   ・表示の不具合
#     「プレースホルダやダミー文言が残っている」← 実機で再確認必須
#
# 書かないこと:
#   ・PSIスコアを測っていないのに「遅い」と断定
#   ・JS描画サイトを「壊れている」と誤判定
#   ・競合比較の推測、相手を貶す言い方
#   ・httpsリダイレクト済みなのに「鍵が付かない」
#   ・tel:があるのに「発信できない」
#   ・新公式があるのに旧サイトの古さだけ突く
#
# 送信直前チェック:
#   □ 課題の各行が audit_notes の粗と1対1
#   □ C0〜C2 を当日再確認した
#
# 良い例:
#   ① スマホ表示で電話番号をタップしても発信につながらない
#   ② トップに「お問い合わせ」導線がなく、下層まで探しにいく必要がある
#   ③ https未対応のため、ブラウザによっては警告が出る
#
# 悪い例:
#   ① サイトが古い（根拠なし）
#   ② SEOができていない（測っていない）
#   ③ デザインが微妙（主観だけ）
#   ④ httpのまま（実際はhttpsへ301）
#   ⑤ 電話が発信できない（実際はtel:あり）
